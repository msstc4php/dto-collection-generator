# dto-collection-generator 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CLI, a programmatic facade and a Composer plugin that read `#[TypedCollection]` attributes and a config file, and write natively typed collection classes over `msstc4php/dto-collection` 1.x for target PHP 8.1–8.5.

**Architecture:** Hexagonal, like dto-generator. Domain (spec, target, diagnostics, method catalogue) → DomainService (validator, class builder) → Application (`Generate` use case and ports) → Infrastructure (config loader, attribute scanner, reflection inspector, php-parser emitter, filesystem writer) → Presentation (CLI, Composer plugin). The shape of every emitted class is fixed by `dto-collection/docs/writing-a-typed-collection.md`. The reference classes are `dto-collection/tests/Fixture/{ItemList,MutableItemList,IntegerList,Odm/PetCollection}.php`.

**Tech Stack:** PHP 8.1+, nikic/php-parser 5, symfony/console, symfony/yaml, PHPUnit 10.5, PHPStan 2 max, Rector 2, PHP-CS-Fixer, deptrac, Infection 0.32.

**Spec:** `docs/internal/specs/2026-10-26-dto-collection-generator-design.md`

## Global Constraints

- The generator runs on PHP **8.1+**: PHPStan `phpVersion: 80100`, `make lint-81` on `php:8.1-cli`, Composer `config.platform.php: 8.1.31`.
- Target versions **8.1–8.5**; `auto` reads the lower bound of `require.php` in the nearest `composer.json`.
- Package `msstc4php/dto-collection-generator`, namespace `MSSTC4PHP\DtoCollectionGenerator`, branch `main`.
- `msstc4php/dto-collection ^1.0` comes from a `path` repository `../dto-collection` with `options: {symlink: false, versions: {"msstc4php/dto-collection": "1.0.0"}}`.
- Generated header line: `// @generated by msstc4php/dto-collection-generator — DO NOT EDIT`.
- Manifest file: `.dto-collection-generator.manifest.json`, next to the config.
- Config file: `dto-collection-generator.yaml`, then `dto-collection-generator.json`. Root keys are `version` (must be 1), `target.php`, `sources`, `collections`, `paths`.
- Exit codes: 0 OK, 1 out of date, 2 generation failed, 3 config or usage error.
- Full names, no abbreviations. Code comments in English, only the non-obvious "why".
- Infection runs with at most 4 threads, and MSI stays at 100 %.
- Tooling is copied from `../dto-collection` (closest PHP floor) and from `../dto-generator`: config `RawSection`, `GeneratedCodePrinter`, writer and plugin.

## Review Focus

1. Element class short name clashes with an import of the emitted file (`Closure`, `ElementType`, `Equality`, `NoDiscard`, `Collection`, or the collection's own short name) → the emitted code refers to it by its fully qualified name and still compiles. Test in Task 9.
2. A DTO file that cannot be loaded (missing parent class, parse error) or an attribute constructor that throws → a diagnostic with file:line; the run does not crash. Test in Task 6.
3. Two specs whose class names differ only in case (`App\ItemList`, `App\itemlist`) → an error: PHP class names and macOS file systems are case-insensitive. Test in Task 8.
4. Running the generator twice gives `unchanged` for every file, and `--check` exits 0. A hand edit of a generated file makes `--check` exit 1 and makes `write` refuse to delete that file when its spec disappears. Test in Tasks 10 and 12.
5. A `float` collection called with ints (`FloatList::of(1, 2)`) under `strict_types` → works (int→float widening). A nullable union `Cat|Dog|null` prints `?T` positions as `Cat|Dog|null`, never `?Cat|Dog`. Test in the Task 13 smoke script and in Task 9.

### Task 9: Emitter

**Files:**
- Create: `src/Application/Port/CodeEmitter.php`, `src/Infrastructure/Emitter/{PhpParserEmitter,GeneratedCodePrinter,ImportTable}.php`, golden files `tests/Fixtures/Emitter/<php>/<ShortName>.php.golden`
- Test: `tests/Integration/Emitter/GoldenEmitterTest.php`, `tests/Unit/Infrastructure/Emitter/ImportTableTest.php`

**Interfaces:**
- Consumes: Task 7 catalogue and `TypeShape`; Task 2 `TargetProfile`; `ClassFacts::isEquatable` for equality.
- Produces: `interface CodeEmitter { emit(CollectionSpec $spec, TargetProfile $target, ClassFacts $facts): string }`. The result is the full file contents, ending in `"\n"`.

Emission rules:
- **Variant pieces.** Interfaces, trait, `final` and doc block come from the spec §8.1 and the reference classes. The ODM class carries `@phpstan-consistent-constructor` and `new static`; the final classes use `new self`.
- **Behaviour traits.** `NumericBehaviour` when `ElementType::isNumeric()`, `TextBehaviour` when `isString()`, each on its own `use` line after the variant trait.

- **Imports.** `ImportTable` holds the fixed imports of the variant plus the element classes.
  - An element class whose short name collides, case-insensitively, with a fixed import, with another element class, or with the collection's own short name is printed fully qualified (`\App\Closure`). So is a class in the global namespace.
