# Configuration

`dto-collection-generator.yaml` (or `.json`) lives in the project. Paths in it are relative to
the file. An unknown key is an error, and every mistake of a file is reported in one run.

```yaml
version: 1
target:
  php: auto            # auto, or a quoted version: '8.1' … '8.5'
sources:               # directories scanned for #[TypedCollection]
  - src/Dto
collections:           # collections of scalars and of classes you cannot annotate
  - class: App\Collection\IntegerList
    variant: immutable # immutable | mutable | odm
    elementType: int   # required here
    nullable: false    # optional, false by default
paths:                 # optional: where the classes of a namespace prefix go
  App\Collection\: src/Collection
```

| Key | Meaning |
|---|---|
| `version` | Required, `1`. |
| `target.php` | `auto` (default) reads the lower bound of `require.php` in the nearest `composer.json`. Without one, 8.1 with a warning; below 8.1 an error (dto-collection needs 8.1); above 8.5, 8.5 with a warning. Write an explicit version in quotes: YAML reads `8.3` as a number. |
| `sources` | Directories to scan. A missing one is a warning. |
| `collections` | Specs written in the config, with the fields of `#[TypedCollection]`. `elementType` is required: there is no marked class to default to. |
| `paths` | Namespace prefix (ending in `\`) to directory. Without a match here, the PSR-4 maps of `autoload` and `autoload-dev` decide; the longest prefix wins. A class that no prefix covers is an error. |

## The attribute

```php
#[TypedCollection(class: 'App\Collection\AnimalList', variant: Variant::Immutable, nullable: true, elementType: 'Cat|Dog')]
```

- `class`: the collection to generate.
- `variant`: `Variant::Immutable`, `Variant::Mutable` or `Variant::Odm`.
- `elementType`: optional. Without it, the element type is the marked class. With it, a
  declaration such as `Animal`, `Cat|Dog` or `Countable&Stringable` that the marked class
  belongs to.
- `nullable`: makes the element type nullable. An ODM collection cannot be nullable.

The generator finds the classes with php-parser, then loads them and creates each attribute
with reflection, so PHP itself evaluates the arguments (`Foo::class`, constants).

## Target versions

| Target | Generated code |
|---|---|
| 8.1 | the base shape |
| 8.2 | intersection element types: `?T` is printed as `(A&B)\|null` |
| 8.3, 8.4, 8.5 | `#[\Override]` on the methods that implement an interface method |

dto-collection 1.x runs on PHP 8.1–8.4; the code for 8.5 is the same contract and is meant for
dto-collection 2.x.

## Checks

Errors stop the run before anything is written:

- the collection name is not a valid class name, or its short name is a reserved word (`List`,
  `Array`, `Mixed`, …);
- two specs name the same class, also when only the letter case differs;
- the class already exists and its file was not written by this generator;
- the collection has the name of its element class;
- the element type does not parse, names a missing class, or names a trait;
- the marked class is not of the declared element type;
- an intersection element type for a target below 8.2;
- an ODM collection whose element type is not a single class or interface: a scalar, a union or
  an intersection (Doctrine ODM's persistent-collection generator cannot print a union return
  type), or doctrine/mongodb-odm is not installed;
- a collection in the global namespace (the file could not import the classes it uses).

A collection whose target file this generator wrote earlier is not loaded for the "already
exists" check: an output for an older dto-collection may no longer load.

An ODM element class without an ODM document attribute is a warning: it may be mapped in XML.

## Writing

- Each file starts with `// @generated by msstc4php/dto-collection-generator — DO NOT EDIT`.
  A file at the target path without that line is never overwritten.
- `.dto-collection-generator.manifest.json`, next to the config, remembers what was generated.
  **Commit it**: `--check` also fails when the manifest is missing or outdated. Its paths are
  relative to the config, so it means the same on every machine.
- A generated file whose spec is gone is deleted, unless it was edited after generation (then it
  is a conflict) or no longer starts with the generated header (then it is left alone with a
  warning).
- Renaming a collection only in letter case (`ItemList` → `Itemlist`) keeps the file on a
  case-insensitive file system instead of deleting the class just written.
- Writes are atomic. Line endings do not count as a change.

## Command line

```
vendor/bin/dto-collection-generator generate [--config=FILE] [--check] [--dry-run] [--format=text|json]
```

| Exit code | Meaning |
|---|---|
| 0 | done (or up to date, with `--check`) |
| 1 | `--check`: something would change |
| 2 | generation failed: a spec error or a file in the way |
| 3 | configuration or usage error |

`--format=json` prints `{status, diagnostics: [{severity, location, message}], changes: [{kind, path}]}`.

From PHP:

```php
use MSSTC4PHP\DtoCollectionGenerator\Application\Generate\Input;
use MSSTC4PHP\DtoCollectionGenerator\Application\Generate\Mode;
use MSSTC4PHP\DtoCollectionGenerator\DtoCollectionGenerator;

$output = DtoCollectionGenerator::generator()(new Input('/path/to/dto-collection-generator.yaml', Mode::Check));
```

## PHPStan and the generated code

The generated classes pass PHPStan at level max. For an intersection element type, one line
carries `@phpstan-ignore return.type, assign.propertyType`: `ElementType::intersection()` is
typed `ElementType<object>`. A generic interface in the element type (`Traversable`, say) needs
type arguments that a spec cannot give, so PHPStan reports a missing iterable value type there.
